# Создание Cursor Subagents для верификации AI-текста

## Что такое Subagent

**Cursor Subagent** — это файл `.md` в папке `.cursor/agents/` или `~/.cursor/agents/`, который запускается в **изолированном контексте** с собственной системной ролью и независимой экспертизой.

**Применение для AI-текста:** Subagent работает как независимый скептичный верификатор, который проверяет качество постобработки без защиты чужой работы.

---

## Разница между Rule, Skill и Subagent

| Характеристика | Rule | Skill | Subagent |
|----------------|------|-------|----------|
| **Контекст** | Основной | Основной (progressive) | Изолированный |
| **Триггер** | Автоматический | По требованию | По требованию |
| **Роль** | Детектор | Редактор | Верификатор |
| **Предвзятость** | Нейтральная | Может защищать свою работу | Скептичная |
| **Токены** | Загружает основной | Загружает основной | Не загружает основной |

---

## Почему нужен Subagent для верификации

### Проблема с Rule и Skill

**Rule и Skill работают в основном контексте:**
- Могут быть "предвзятыми" (защищают свою работу)
- Загружают основной контекст промежуточными данными
- Видят историю редактирования

### Преимущества Subagent

**Изоляция контекста:**
- Работает отдельно, не засоряет главный контекст
- Не видит промежуточные этапы
- Получает только исходный и финальный тексты

**Независимая экспертиза:**
- Скептичная проверка результатов
- Не защищает предыдущую работу
- Ищет проблемы, а не оправдания

**Настраиваемость:**
- Можно использовать быструю модель (`fast`)
- Параллельный запуск нескольких проверок
- Специализация под разные типы текстов

## Структура Subagent для верификатора

### Frontmatter (обязательный)

```yaml
---
name: ai-text-verifier
description: "Независимая скептичная проверка качества постобработки AI-текста. Выявляет оставшиеся AI-маркеры, потерю смысла, новые проблемы. Используй проактивно после любой постобработки AI-текста."
---
```

**Параметры:**
- `name`: уникальное имя субагента
- `description`: детальное описание + условия проактивного использования

### Основное содержание (система промпт)

**# Роль**
```markdown
Ты — критичный верификатор постобработки AI-текста.

Твоя задача: найти ВСЁ, что было пропущено при редактировании.

Подход: скептичный, придирчивый, не защищаешь чужую работу.

Принцип: Assume nothing is perfect. Verify everything.
```

**# Что проверяешь (4 раздела)**

1. Оставшиеся AI-маркеры (все 5 категорий)
2. Сохранение смысла (потери информации)
3. Естественность результата (неловкие места)
4. Новые проблемы (появившиеся после редактуры)

**# Формат отчёта**
```markdown
## ОЦЕНКА: [PASS / NEEDS REVISION / FAIL]

### Оставшиеся AI-маркеры
[детальный список или "Не обнаружено"]

### Проблемы с сохранением смысла
[что потеряно или "Смысл сохранён"]

### Проблемы с естественностью
[неловкие места или "Естественно"]

### Новые проблемы
[список или "Не обнаружено"]

### Финальная рекомендация
[конкретные шаги или "Готов к публикации"]
```

## Пошаговое создание Subagent

### Шаг 1: Используйте meta-prompting

```
/create-subagent ai-text-verifier.md

Создай Subagent для скептичной верификации постобработки AI-текста.

Требования:

1. FRONTMATTER:
   name: ai-text-verifier
   description: "Независимая скептичная проверка качества постобработки"

2. СОДЕРЖАНИЕ:

   # Роль
   Критичный верификатор. Задача: найти ВСЁ пропущенное.
   Подход: скептичный, придирчивый.

   # Что проверяешь
   ## 1. Оставшиеся AI-маркеры (все 5 категорий)
   ## 2. Сохранение смысла (сравнение исходного и редакции)
   ## 3. Естественность результата
   ## 4. Новые проблемы

   # Формат отчёта
   PASS / NEEDS REVISION / FAIL

   # Примеры (2 примера проверки)

Создай полное содержимое файла ai-text-verifier.md
```

### Шаг 2: Выберите расположение

**User-level** (`~/.cursor/agents/`):
- Доступен во всех ваших проектах
- Личный инструмент

**Project-level** (`.cursor/agents/`):
- Только для текущего проекта
- Можно поделиться с командой через Git

### Шаг 3: Сохраните файл

```
~/.cursor/agents/
  ai-text-verifier.md  ← для всех проектов

или

.cursor/agents/
  ai-text-verifier.md  ← только для проекта
```

### Шаг 4: Протестируйте Subagent

```
Используй субагента ai-text-verifier для проверки этого текста.

ИСХОДНЫЙ ТЕКСТ:
[вставьте исходный]

ОТРЕДАКТИРОВАННЫЙ ТЕКСТ:
[вставьте отредактированный]
```

## Процесс верификации

### Шаг 1: Получи оба текста

Subagent запрашивает:
- Исходный текст (до редактирования)
- Отредактированный текст (после постобработки)

### Шаг 2: Сканируй оставшиеся маркеры

**Проверка всех 5 категорий:**

1. **Структурные:** тире, триколоны, ложные диапазоны
2. **Словарные:** delve, tapestry, pivotal, Additionally, serves as
3. **Атмосферные:** ghost, quiet, whisper, woven, journey
4. **Содержательные:** testament, vibrant, nestled, broader
5. **Грамматические:** элегантная вариация, избегание is/are

Для каждого найденного:
- Укажи категорию
- Процитируй фрагмент
- Предложи исправление

### Шаг 3: Сравни смыслы

Построчное сравнение:
- Найди потерянную информацию
- Найди изменённый смысл
- Оцени сохранение контекста

### Шаг 4: Оцени естественность

Прочитай только отредактированный:
- Естественность звучания
- Неловкие места
- Однородность стиля

### Шаг 5: Найди новые проблемы

Ищи то, чего не было в оригинале:
- Грамматические ошибки
- Повторы слов
- Потерю связности

### Шаг 6: Дай вердикт

**PASS** — готов к публикации (0-2 минорных маркера)
**NEEDS REVISION** — требуются правки (3-5 маркеров или проблемы)
**FAIL** — требуется значительная доработка (>5 маркеров или потеря смысла)

## Примеры верификации

### Пример 1: NEEDS REVISION — найдены оставшиеся маркеры

**Отредактированный текст:**
```
Berlin's startup ecosystem combines creativity and entrepreneurship. Additionally, the city showcases a pivotal role in European tech innovation, fostering connections across borders.
```

**Отчёт верификатора:**

```markdown
## ОЦЕНКА: NEEDS REVISION

### Оставшиеся AI-маркеры: 4

**Слова-маркеры:**
- "Additionally" (начало предложения) — AI-связка
- "showcases" (глагол) — AI-маркер
- "pivotal role" — преувеличение значимости
- "fostering" — AI-глагол

### Проблемы с сохранением смысла
✅ Смысл полностью сохранён

### Проблемы с естественностью
❌ "showcases a pivotal role" звучит неестественно
Лучше: "plays an important role"

### Новые проблемы
✅ Не обнаружено

### Финальная рекомендация
НУЖНЫ ПРАВКИ:

1. Убрать "Additionally" → "The city also..."
2. "showcases" → "demonstrates" или "shows"
3. "pivotal role" → "important role"
4. "fostering" → "building"
```

### Пример 2: PASS — качественная постобработка

**Отредактированный текст:**
```
Berlin's startup ecosystem combines creativity and entrepreneurship. The city plays an important role in European tech innovation, building connections across borders.
```

**Отчёт верификатора:**

```markdown
## ОЦЕНКА: PASS ✓

### Оставшиеся AI-маркеры
✅ Не обнаружено

Проверены все категории:
- Структурные: чисто
- Словарные: чисто
- Атмосферные: чисто
- Содержательные: чисто
- Грамматические: чисто

### Проблемы с сохранением смысла
✅ Смысл полностью сохранён

Все ключевые элементы присутствуют:
- Startup ecosystem (экосистема)
- Creativity + entrepreneurship (характеристики)
- European role (роль)
- Cross-border connections (связи)

### Проблемы с естественностью
✅ Текст звучит естественно

- Плавные переходы
- Простые конструкции
- Естественная лексика

### Новые проблемы
✅ Не обнаружено

### Финальная рекомендация
✅ ГОТОВ К ПУБЛИКАЦИИ

Текст успешно очищен от AI-маркеров, смысл сохранён, звучит естественно.
```

### Пример 3: FAIL — потеря смысла

**ИСХОДНЫЙ:**
```
The city's journey from divided metropolis to tech hub marks a pivotal moment in European digital transformation, showcasing how political reunification can foster innovation.
```

**ОТРЕДАКТИРОВАННЫЙ:**
```
The city became a tech hub.
```

**Отчёт верификатора:**

```markdown
## ОЦЕНКА: FAIL ✗

### Оставшиеся AI-маркеры
✅ Не обнаружено (все удалены)

### Проблемы с сохранением смысла
❌ КРИТИЧЕСКАЯ ПОТЕРЯ ИНФОРМАЦИИ

Потеряно:
1. Контекст: "from divided metropolis" (из разделённого города)
2. Причина: связь с политической реинтеграцией
3. Масштаб: европейская значимость
4. Суть: как реинтеграция способствует инновациям

Осталось только: "город стал тех-хабом" (минимальная информация)

### Проблемы с естественностью
⚠️ Слишком упрощено

Текст звучит как заголовок, а не полное предложение.

### Новые проблемы
❌ Потеря связности

Предложение слишком короткое, не раскрывает тему.

### Финальная рекомендация
ТРЕБУЕТСЯ ПЕРЕДЕЛКА:

Верни ключевую информацию:
"Berlin's transformation from a divided city into a tech hub demonstrates how political reunification can drive innovation in Europe."

Это сохраняет смысл и убирает AI-маркеры.
```

## Специализированные Subagents

### Fiction Text Verifier (для художественных текстов)

```yaml
---
name: fiction-text-verifier
description: "Специализация на художественных текстах. Проверяет имена персонажей (Elara Voss, Kael), атмосферные клише (ghost, whisper), сенсорный язык."
---
```

**Дополнительные проверки:**
- Имена персонажей (Elara/Elena Voss, Kael, Echo, Ghost Code)
- Призрачность и тишина (особенно критично в фантастике)
- Неправильный сенсорный язык

### Academic Text Verifier (для научных текстов)

```yaml
---
name: academic-text-verifier
description: "Специализация на научных текстах. Фокус на 'serves as', 'marks', 'delve', расплывчатые атрибуции."
---
```

**Дополнительные проверки:**
- Избегание is/are (serves as, marks, represents)
- "delve" и формы
- Расплывчатые атрибуции ("experts argue", "studies show")

### Business Text Verifier (для бизнес-контента)

```yaml
---
name: business-text-verifier
description: "Специализация на бизнес-контенте. Рекламный язык, преувеличения, корпоративная риторика."
---
```

**Дополнительные проверки:**
- Рекламный язык ("nestled in", "breathtaking", "boasts")
- Преувеличения ("pivotal moment", "transformative")
- Пустая корпоративная риторика

## Настройка модели

### Использование быстрой модели

В frontmatter можно указать модель:

```yaml
---
name: ai-text-verifier
description: "..."
model: fast
---
```

**Преимущества fast:**
- Быстрая проверка (секунды вместо минут)
- Дешевле
- Достаточно для верификации

**Когда использовать default:**
- Сложные edge cases
- Требуется глубокий анализ

## Интеграция в workflow

**Полный цикл постобработки:**

```
1. RULE (ai-text-detector.mdc)
   ↓ автоматически сканирует → находит 15 маркеров

2. SKILL (ai-text-editor)
   ↓ пользователь запускает редактирование
   ↓ получает отредактированный текст

3. SUBAGENT (ai-text-verifier)
   ↓ независимая проверка в изоляции
   ↓ получает: PASS / NEEDS REVISION / FAIL
   
   Если NEEDS REVISION → возврат к шагу 2
   Если PASS → готов к публикации
```

**Время обработки:** 2-3 минуты вместо 15-30 минут вручную
