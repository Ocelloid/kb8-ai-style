# Создание Cursor Rules для обнаружения AI-маркеров

## Что такое Rule

**Cursor Rule** — это файл `.mdc` в папке `.cursor/rules/`, который автоматически активируется при работе с определёнными файлами и предоставляет контекст AI-агенту.

**Применение для AI-маркеров:** Rule работает как пассивный детектор, который автоматически сканирует тексты и предупреждает о найденных маркерах.

---

## Зачем нужен Rule для AI-текстов

### Проблема
Каждый раз вручную проверять текст по чек-листу из 50+ маркеров долго и можно пропустить паттерны.

### Решение
Rule автоматически анализирует текст при открытии файла или по запросу:
- Сканирует все 5 категорий маркеров
- Выдаёт предупреждения в комментариях
- Показывает счётчик маркеров
- Предлагает запустить редактор

---

## Структура Rule для AI-детектора

### Frontmatter (обязательный)

```yaml
---
description: "Автоматический детектор AI-маркеров в текстах"
globs: 
  - "articles/**/*.md"
  - "blog/**/*.md"
  - "content/**/*.md"
alwaysApply: false
---
```

**Параметры:**
- `description`: краткое описание (показывается в интерфейсе)
- `globs`: паттерны файлов, к которым применяется правило
- `alwaysApply: false`: активируется только для указанных файлов (не для всех)

### Основное содержание

**Роль:** Задаём роль эксперта-детектора
```markdown
Ты — детектор AI-маркеров в текстах.
Твоя задача — обнаружить характерные паттерны генеративных моделей.
```

**Что проверяется:**
1. Структурные паттерны (тире, триколоны, правило троек)
2. Слова-маркеры (delve, tapestry, pivotal, etc.)
3. Атмосферные клише (quiet, ghost, whisper, woven)
4. Содержательные паттерны (pivotal moment, testament)
5. Грамматические тики (serves as, ложные диапазоны)

**Формат вывода:**
- Количество маркеров по категориям
- Топ-5 самых явных
- Оценка вероятности AI (0-100%)
- Рекомендация: запустить редактор (да/нет)

## Пошаговое создание Rule

### Шаг 1: Используйте команду Cursor

```
/create-rule ai-text-detector

Создай файл .mdc (Cursor Rule) для автоматического обнаружения AI-маркеров в текстах.

Требования к Rule:

1. FRONTMATTER:
   - description: краткое описание правила
   - globs: ["articles/**/*.md", "blog/**/*.md", "content/**/*.md"]
   - alwaysApply: false

2. СОДЕРЖАНИЕ:
   Роль: детектор AI-маркеров

   Проверяет:
   - Структурные паттерны (тире, триколоны)
   - Словарь (delve, tapestry, intricate, pivotal, etc.)
   - Атмосферу (quiet, ghost, whisper)
   - Содержание (pivotal moment, testament)
   - Грамматические тики

   Формат вывода:
   - Количество найденных маркеров по категориям
   - Топ-5 самых явных
   - Оценка вероятности AI (0-100%)
   - Рекомендация: запустить редактор (да/нет)

3. ПРИМЕРЫ:
   Добавь 2 примера использования

Создай полное содержимое файла ai-text-detector.mdc
```

### Шаг 2: Сохраните файл

Сохраните результат в:
```
ваш-проект/
  .cursor/
    rules/
      ai-text-detector.mdc  ← здесь
```

### Шаг 3: Подключите файлы контекста

Для более точной работы подключите материалы с описанием маркеров:

```
@Материалы/01 - Структурные паттерны.md
@Материалы/02 - Слова-маркеры.md
@Материалы/03 - Атмосферные клише.md
@Материалы/04 - Содержательные паттерны.md
@Материалы/05 - Грамматические тики.md
```

### Шаг 4: Протестируйте Rule

**Способ 1: Автоматическая активация**
Откройте файл в папках `articles/`, `blog/` или `content/` — Rule активируется сам.

**Способ 2: Ручная активация**
```
@ai-text-detector проверь этот файл
```

## Расширение Rule

### Добавьте дополнительные проверки

**Имена персонажей в фантастике:**
```markdown
- Elara Voss / Elena Voss (женские персонажи)
- Kael (мужские персонажи)
- Echo (любовные интересы)
- Ghost Code (AI-антагонисты)
```

**Подсчёт частоты "quiet":**
```markdown
Норма: не более 1 раза на 500 слов
Если больше → сильный AI-маркер
```

**Формула сарказма "X с Y и Z":**
```markdown
Паттерн: "[предмет] — это просто X с Y и Z"
Пример: "тролль с Reddit с Wi-Fi и миллиардами"
```

**Title Case в заголовках:**
```markdown
Все слова с заглавной буквы → AI-маркер
Пример: "The Future Of Remote Work" (вместо "The future of remote work")
```

## Примеры использования

### Пример 1: Текст с высокой концентрацией маркеров

**Входной текст:**
```
The innovative startup ecosystem in Berlin has evolved into a vibrant tapestry of creativity and entrepreneurship. This dynamic landscape is not just about technology—it's about fostering human connections and cultivating meaningful innovations.
```

**Вывод Rule:**
```markdown
## 📊 AI-МАРКЕРЫ ОБНАРУЖЕНЫ: 12

### Структурные паттерны: 1
- "not just about X—it's about Y" (тире + отрицательная конструкция)

### Слова-маркеры: 7
- innovative, vibrant, tapestry, dynamic, landscape, fostering, cultivating

### Атмосферные клише: 1
- tapestry (метафора ткачества)

### Содержательные паттерны: 2
- vibrant (рекламный язык)
- dynamic landscape (пустая абстракция)

### Грамматические тики: 1
- элегантная вариация ("ecosystem" → "landscape")

---

### 🎯 Оценка вероятности AI: 85%

### 💡 Рекомендация: ДА
Запустите редактор для удаления маркеров.
```

### Пример 2: Естественный текст

**Входной текст:**
```
Yesterday I went to a new restaurant downtown. The food was simple but delicious. The waiter was friendly and brought our order quickly. Prices were a bit high, but the quality was worth it.
```

**Вывод Rule:**
```markdown
## 📊 AI-МАРКЕРЫ: 0

### Оценка вероятности AI: 5%

### Рекомендация: НЕТ
Текст выглядит естественным, редактирование не требуется.
```

## Настройка под ваши задачи

### Измените globs на ваши папки

```yaml
globs:
  - "writing/**/*.md"      # ваши статьи
  - "blog-drafts/**/*.md"  # черновики
  - "docs/**/*.md"         # документация
```

### Добавьте другие расширения

```yaml
globs:
  - "**/*.txt"   # текстовые файлы
  - "**/*.docx"  # Word документы (если есть поддержка)
```

### Настройте порог срабатывания

```markdown
Если маркеров < 5 → вероятность < 40% → рекомендация НЕТ
Если маркеров 5-10 → вероятность 40-70% → рекомендация ВОЗМОЖНО
Если маркеров > 10 → вероятность > 70% → рекомендация ДА
```
